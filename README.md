# PrivateMesh relay-server

Один файл, ноль зависимостей от базы данных. Сервер видит только:
- `to` — id получателя (hex-хэш его публичного ключа, не имя/номер),
- `ciphertext` — зашифрованный blob, который он прочитать не может.

Ничего не пишет на диск. Офлайн-очередь хранится в оперативной памяти
и живёт максимум 48 часов, после чего сообщение удаляется, если
получатель не забрал его.

## Запуск локально

```bash
cd relay-server
npm install
npm start
```

По умолчанию слушает `ws://localhost:8080`.

## Бесплатный деплой (варианты)

### Render.com (проще всего)
1. Залейте папку `relay-server/` в свой GitHub-репозиторий.
2. На render.com → New → Web Service → подключите репозиторий.
3. Build command: `npm install`, Start command: `npm start`.
4. Render выдаст публичный `wss://<ваш-сервис>.onrender.com` — это и есть
   адрес relay для приложения. Free-тариф "засыпает" при простое —
   первое сообщение после паузы может прийти с задержкой в секунды.

### Fly.io
1. `fly launch` в папке `relay-server/` (сгенерирует `fly.toml`).
2. `fly deploy`.
3. Адрес: `wss://<app-name>.fly.dev`.

### Свой VPS
`node server.js` за Nginx/Caddy с TLS-терминацией (нужен `wss://`,
незашифрованный `ws://` через открытый интернет использовать нельзя —
это отдельный транспортный слой поверх E2E-шифрования, но лучше не
давать провайдеру/соседям по сети даже метаданные соединения в открытую).

## Важно про доверие к серверу

Сервер не может прочитать сообщения (E2E-шифрование на стороне
приложения), но **видит**, кто (по анонимному id) и когда кому писал —
это метаданные, не содержимое. Если это критично, деплойте на VPS,
которому доверяете, либо периодически меняйте id.
